## 🔍 Introduction & Concepts

### db.create_all() vs Database Migrations

Your project uses a **hybrid approach** that's common in Flask development:

| Method | Purpose | When to Use | Pros | Cons |
|--------|---------|-------------|------|------|
| **db.create_all()** | Creates all tables from scratch | Development, Testing | Fast setup, Simple | No version control, Data loss risk |
| **Database Migrations** | Incremental schema changes | Production, Team work | Version control, Data safety | More complex, Requires planning |

## 📝 Common Migration Scenarios

### 1. Adding a New Column

**Scenario:** Add a `bio` field to the User model.

**Step 1:** Modify `project_flask/models.py`
```python
class User(db.Model):
    # ... existing fields ...
    bio = db.Column(db.Text, nullable=True)  # New field
```

**Step 2:** Generate migration
```bash
export FLASK_APP=project_flask
flask db migrate -m "Add bio field to User model"
```

**Generated migration file:**
```python
def upgrade():
    # ### commands auto generated by Alembic - please adjust! ###
    op.add_column('users', sa.Column('bio', sa.Text(), nullable=True))
    # ### end Alembic commands ###

def downgrade():
    # ### commands auto generated by Alembic - please adjust! ###
    op.drop_column('users', 'bio')
    # ### end Alembic commands ###
```

**Step 3:** Apply migration
```bash
flask db upgrade
```

## 📊 Data Migration Techniques

### Migrating Existing Data

Sometimes you need to transform existing data, not just schema.

**Example:** Split full name into first/last name in UserProfile.

**Step 1:** Add new fields
```python
class UserProfile(db.Model):
    # ... existing fields ...
    full_name_deprecated = db.Column(db.String(255), nullable=True)  # Renamed old field
    first_name = db.Column(db.String(120), nullable=True)  # New field
    last_name = db.Column(db.String(120), nullable=True)   # New field
```

**Step 2:** Create custom migration
```bash
flask db migrate -m "Split full name into first and last name"
```

**Step 3:** Edit migration file to include data transformation
```python
from alembic import op
import sqlalchemy as sa

def upgrade():
    # Add new columns
    op.add_column('user_profiles', sa.Column('first_name', sa.String(120), nullable=True))
    op.add_column('user_profiles', sa.Column('last_name', sa.String(120), nullable=True))
    
    # Migrate data
    connection = op.get_bind()
    result = connection.execute(
        "SELECT user_id, display_name FROM user_profiles WHERE display_name IS NOT NULL"
    )
    
    for user_id, display_name in result:
        if display_name and ' ' in display_name:
            names = display_name.split(' ', 1)
            first_name = names[0]
            last_name = names[1] if len(names) > 1 else ''
            
            connection.execute(
                "UPDATE user_profiles SET first_name = %s, last_name = %s WHERE user_id = %s",
                (first_name, last_name, user_id)
            )

def downgrade():
    # Restore data to display_name before dropping columns
    connection = op.get_bind()
    connection.execute(
        "UPDATE user_profiles SET display_name = CONCAT(first_name, ' ', last_name) "
        "WHERE first_name IS NOT NULL AND last_name IS NOT NULL"
    )
    
    op.drop_column('user_profiles', 'last_name')
    op.drop_column('user_profiles', 'first_name')
```

### Batch Operations for Large Tables

For tables with millions of records:

```python
def upgrade():
```

## ⚡ Best Practices & Safety

### Before Running Migrations

1. **Always Backup Production Data**
   ```bash
   # PostgreSQL backup
   pg_dump -h localhost -U appuser test_db > backup_$(date +%Y%m%d_%H%M%S).sql
   
   # Restore if needed
   psql -h localhost -U appuser -d test_db < backup_file.sql
   ```

2. **Test Migrations on Copy of Production Data**
   ```bash
   # Create test database with production data
   createdb test_migration
   pg_restore -d test_migration production_backup.sql
   
   # Test migration
   DATABASE_URL=postgresql://user:pass@localhost/test_migration flask db upgrade
   ```

3. **Review Generated Migrations**
   ```bash
   # Always check the generated migration file
   cat migrations/versions/latest_migration.py
   
   # Understand what SQL will be executed
   flask db show head
   ```

### During Migration Development

1. **Use Descriptive Messages**
   ```bash
   # Good
   flask db migrate -m "Add user bio field with 500 char limit"
   
   # Bad
   flask db migrate -m "changes"
   ```

2. **Keep Migrations Small and Focused**
   ```bash
   # Good - separate concerns
   flask db migrate -m "Add Category model"
   flask db migrate -m "Link Building to Category"
   
   # Avoid - too many changes at once
   flask db migrate -m "Add categories, modify buildings, update users, fix indexes"
   ```

3. **Test Both Upgrade and Downgrade**
   ```bash
   # Test the migration
   flask db upgrade
   
   # Test the rollback
   flask db downgrade
   
   # Apply again to ensure consistency
   flask db upgrade
   ```

### Production Safety Measures

1. **Use Maintenance Mode**
   ```bash
   # Put app in maintenance mode before migration
   # Apply migration
   # Remove maintenance mode
   ```

2. **Monitor Migration Progress**
   ```bash
   # For long-running migrations, monitor progress
   flask db upgrade --sql > migration.sql  # See what will run
   psql -d database -f migration.sql        # Run with progress monitoring
   ```

3. **Have Rollback Plan**
   ```bash
   # Know how to rollback
   flask db current  # Remember current version
   flask db downgrade [previous_revision]
   ```

## 🚀 Production Deployment

### Zero-Downtime Migration Strategy

1. **Backward Compatible Changes First**
   ```bash
   # Step 1: Add new optional column
   flask db migrate -m "Add new optional field"
   flask db upgrade
   
   # Deploy new code that can handle both old and new schema
   
   # Step 2: Populate new column
   flask db migrate -m "Populate new field from existing data"
   flask db upgrade
   
   # Step 3: Remove old column
   flask db migrate -m "Remove deprecated field"
   flask db upgrade
   ```

2. **Blue-Green Deployment with Migrations**
   ```bash
   # Green environment (new)
   export DATABASE_URL=postgresql://user:pass@localhost/green_db
   flask db upgrade
   
   # Test thoroughly
   # Switch traffic to green
   # Keep blue as fallback
   ```

## 🔧 Troubleshooting Guide

### Common Issues and Solutions

#### 1. "No changes in schema detected"

**Problem:** Migration not generating despite model changes.

**Solutions:**
```bash
# Check if Flask can import your models
export FLASK_APP=project_flask
python -c "from project_flask.models import User; print('Models imported successfully')"

# Ensure models are imported in __init__.py or referenced somewhere
# Check for typos in model definitions

# Force create a manual migration
flask db revision -m "Manual migration"
```

#### 2. "Target database is not up to date"

**Problem:** Database schema doesn't match migration history.

**Solutions:**
```bash
# Check current migration in database vs files
flask db current
flask db history

# If database is ahead, stamp it to match
flask db stamp head

# If database is behind, upgrade
flask db upgrade

# If completely out of sync, might need to recreate
```

#### 3. "Duplicate column/table" errors

**Problem:** Trying to create something that already exists.

**Solutions:**
```bash
# Check what's actually in database
python scripts/check_db_tables.py

# Manually edit migration to handle existing items
# In migration file:
def upgrade():
    # Check if column exists before adding
    bind = op.get_bind()
    inspector = inspect(bind)
    columns = [col['name'] for col in inspector.get_columns('users')]
    
    if 'bio' not in columns:
        op.add_column('users', sa.Column('bio', sa.Text()))
```

#### 4. Data type conflicts

**Problem:** PostgreSQL vs SQLite compatibility issues.

**Solutions:**
```python
# Use SQLAlchemy variants
from sqlalchemy.dialects.postgresql import JSONB

# In models.py
preferences = db.Column(JSONB().with_variant(db.JSON, "sqlite"), 
                       server_default="{}", nullable=False)
```

#### 5. Foreign key constraint errors

**Problem:** Cannot add/remove foreign keys due to data constraints.

**Solutions:**
```python
def upgrade():
    # Disable foreign key checks temporarily
    op.execute("SET foreign_key_checks = 0")
    
    # Make changes
    op.drop_constraint('fk_constraint_name', 'table_name', type_='foreignkey')
    op.create_foreign_key('new_fk_name', 'source_table', 'target_table', 
                         ['local_col'], ['remote_col'])
    
    # Re-enable foreign key checks
    op.execute("SET foreign_key_checks = 1")
```

### Performance Optimization

For large database migrations:

```python
def upgrade():
    # Use batch operations
    with op.batch_alter_table('large_table', schema=None) as batch_op:
        batch_op.add_column(sa.Column('new_field', sa.String(50)))
        batch_op.create_index('idx_new_field', ['new_field'])
    
    # Process in chunks for large datasets
    bind = op.get_bind()
    offset = 0
    batch_size = 10000
    
    while True:
        result = bind.execute(f"""
            UPDATE large_table SET new_field = 'default_value'
            WHERE id IN (
                SELECT id FROM large_table 
                WHERE new_field IS NULL
                LIMIT {batch_size} OFFSET {offset}
            )
        """)
        
        if result.rowcount == 0:
            break
        
        offset += batch_size
        print(f"Processed {offset} records...")
```
